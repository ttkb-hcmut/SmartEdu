# ADR-0008: Typed Retrieval Policies and Evidence-Ledger Benchmark

Status: accepted

## Context

Retrieval experiments need stable arm definitions, truthful provenance, and a
production-compatible execution path. The earlier agentic harness globally
re-ranked all candidates to a final top five, which could remove evidence from
an earlier hop before the answerer saw it. Model-generated scope and ranking
arguments would also make runs incomparable.

## Decision

- Treat policy and harness as separate typed, versioned contracts. Resolve them
  once into an immutable `RetrievalRunContext`; agents and tools only consume it.
- Keep course scope and top-k outside model-generated tool arguments. Repository
  adapters own store-specific filtering.
- Add `baseline-v4` with `agentic-v3`: parallel deterministic seed, append-only
  URI-deduplicated evidence ledger, up to four one-call focused retrieval rounds,
  then a separate no-tool answerer.
- Permit RRF only inside one retrieval round. It orders the complete union and
  never deletes accepted evidence.
- Keep V2 and fanout behavior frozen as controls. Harness selection is explicit;
  missing implementations fail instead of falling back.
- Digest prompts, tools, model profile, temperature, budgets, and ranking/context
  limits. A semantic change requires a new policy or harness ID.
- Record mechanical validity and node configuration. Empty retrieval is valid;
  repository/model failure is invalid; blocked, repeated, or invalid calls are
  traced rather than inferred from model text.

## Consequences

V3 answer context has zero selection loss by construction and can be evaluated
at paragraph and retrieval-round level. It costs one 120B aggregation phase plus
a separate 120B answer call, and the append-only ledger increases prompt size;
the contract therefore includes a 160,000-character pre-round guard and
1,000-character evidence excerpts.

Benchmark ingestion remains a separate dual-index operation. A scored run must
link the exact corpus manifest digest and a completed ingestion report for that
same corpus.

## Rejected alternatives

- Global top-k RRF after all hops: cheap, but destroys causal multi-hop evidence.
- Let the aggregator filter the ledger: makes selection unobservable and repeats
  the same loss behind model judgment.
- Give raw repository tools to the aggregator: leaks scope and ranking controls
  into model arguments.
- Rewrite V2 in place: invalidates historical comparisons.
- Per-course Neo4j databases: stronger isolation, but adds provisioning work not
  justified for the prototype benchmark.
